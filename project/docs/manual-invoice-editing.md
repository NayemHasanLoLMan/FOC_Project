# Edit an invoice

On Jobs, choose **Edit**, or open **View** and choose **Edit / add information**. Add missing fields or change existing invoice information. You can add, remove or change goods, quantities, units and unit values. Blank fields remain empty. Net weight is not offered. Bangladesh keeps its existing fields. India adds HS codes, discharge port and shipment terms, and labels its address as IEC/PAN/GST; unsupported Bangladesh-only TIN/import-cover-note fields are not offered for India. India's country, currency and template are protected.

Choose **Save new invoice version**. The running worker uses the existing shared template and saves a separate Excel file; the original invoice remains available in history. No OCR or image-model inference is repeated for a manual save. If processing is paused, your change waits until processing resumes. A stopped system must be started with the normal single command.

Goods changes recalculate line amounts to cents. Bangladesh's automatic total uses the nearest whole dollar; India's uses cents, both half up. You may enter a different total. New rows need their own unit value; the editor does not guess a new rate. Missing quantity or price on a new/repriced row leaves its line value and automatic total empty. For India, description/HS-only edits preserve existing source line amounts and the declared total. Unchanged source-priced rows retain their original amounts even when another row changes. A blank India total while modifying goods means it will be calculated when saved; enter an explicit total to override that calculation.

Original PDF images and readings remain available and are labelled as original readings. Changed descriptions, quantities, units or India HS codes lose their old row source attribution; manually entered facts are not presented as PDF extractions. Unchanged rows keep their attribution. Editing does not alter the PDF or teach the extractor a rule for later PDFs.

Only the latest completed Bangladesh or India invoice can be edited. Concurrent or stale submissions are rejected; reload the latest invoice before trying again. Repeated delivery of the same save request does not create duplicate work. Retry preserves an interrupted edit; **Create another invoice** processes the PDF afresh and discards manual overrides for that new version. Jordan editing remains unavailable. India folder watching is still disabled pending later acceptance stages; standalone CLI exports are not automatically dashboard jobs.

## API

GET /jobs/{job_id}/edit opens the editor. POST /api/jobs/{job_id}/edit uses the existing matching Origin and X-CSRF-Token protection, plus a UUID request_id, current completed attempt_id and nonempty changes object. The body limit is 65,536 bytes. See [OpenAPI](openapi.json) for the complete field allowlist and limits.

Bangladesh example changes: {"tin_number":"User supplied identifier","gross_weight_kg":12.5}. India example: {"port_of_discharge":"User supplied port","shipment_terms":"FOB"}. Send only changed fields. An empty string clears an optional field. If items is supplied it replaces the goods list, limited to 200 rows, each containing source_index (original zero-based row or null), description, quantity, unit and unit_price. India rows also require hs_code (text up to 20 characters, null/empty to clear; leading zeros preserved). BD rows reject hs_code. India's changes reject destination_country, tin_number and import_cover_note; shared source/template/currency/provenance properties cannot be edited. Values are validated for the immutable job region in the HTTP API, store and worker. Server calculations are authoritative.

Schema 5 originally added jobs.manual_edit_json; the current system uses schema 6 with immutable job region. This India editing update requires no migration. The queued edit records its base attempt and changes, copied into the new attempt metadata. Changes are validated before queuing and again when preparing the workbook. Existing publication, hash verification and crash recovery apply. See [India Fix 11](india_fix11_manual_editing.md) for acceptance evidence.
